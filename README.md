# DevSecOps CI/CD Operations Lab — автоматизация безопасного развёртывания приложения

## Цель проекта

**Организовать автоматизированный CI/CD-процесс, выполнять QA и SAST и развёртывать приложение с использованием Docker и Kubernetes**.

Самостоятельно организовать проект в Git, развернуть GitLab и GitLab Runner на виртуальной машине, подготовить приложение, контейнеризировать его и настроить автоматизированный процесс.

Затем добавить автоматический QA и SAST, выполнить развёртывание в Kubernetes и настроить мониторинг с использованием Prometheus и Grafana.

Рабочая программа непосредственно предусматривает Git, GitLab/GitLab Runner, автоматический QA, VM/Docker, Kubernetes, Prometheus и Grafana. 

**Исходные условия:** у преподавателя и студентов нет готового GitLab, GitLab Runner, учебного проекта или готового стенда. Необходимые компоненты создаются по ходу проекта.

**Порядок обучения:**

**Git → GitLab → GitLab Runner → CI/CD → FastAPI → QA → SAST → Docker → Kubernetes → Prometheus → Grafana → итоговая проверка.**

# Этапы выполнения

## 1. 🟢 Организовать проект в Git

**Дано:** готового учебного проекта нет.

**Задача:** создать проект и организовать его хранение с использованием Git.

**Решение:**

1. Создать каталог проекта.
2. Создать необходимые файлы.
3. Инициализировать Git.
4. Добавить файлы.
5. Выполнить commit.
6. Проверить историю изменений.

**Результат:** создан Git-репозиторий учебного проекта.

**Проверка:** Git отображает репозиторий и историю изменений.

**Соответствие программе:** П.З.1 «Git. Организация проекта». 

---

## 2. 🟢 Развернуть GitLab и GitLab Runner

**Дано:** Git-проект существует, но централизованная CI/CD-платформа отсутствует.

**Задача:** подготовить GitLab и исполнитель автоматизированных заданий.

**Решение:**

1. Подготовить виртуальную машину.
2. Развернуть GitLab.
3. Создать проект.
4. Перенести Git-репозиторий.
5. Развернуть GitLab Runner.
6. Зарегистрировать Runner.
7. Проверить его состояние.

**Результат:** GitLab и GitLab Runner готовы к выполнению автоматизированных заданий.

**Проверка:** Runner отображается в GitLab.

**Соответствие программе:** П.З.2 «Развёртывание GitLab и GitLab Runner на виртуальной машине». 

---

## 3. 🟢 Подготовить FastAPI-приложение

**Дано:** инфраструктура GitLab подготовлена, но отсутствует минимальное приложение для последующей автоматизации.

**Задача:** подготовить простое учебное приложение.

**Решение:**

1. Создать минимальное FastAPI-приложение.
2. Добавить один endpoint.
3. Запустить приложение.
4. Проверить его работу.
5. Проверить запрос к приложению.

**Результат:** получено работающее FastAPI-приложение.

**Проверка:** приложение отвечает на запрос.

**Соответствие программе:** лекция 2.3 «Реализация веб-шлюзов микросервисов на Flask и FastAPI» и П.З.3 «FastAPI, Postman, интеграции».  

---

## 4. 🟡 Настроить CI/CD

**Дано:** GitLab и Runner работают, но автоматизированный процесс отсутствует.

**Задача:** настроить автоматическое выполнение заданий проекта.

**Решение:**

1. Создать конфигурацию CI/CD.
2. Добавить простое задание.
3. Сохранить конфигурацию в Git.
4. Запустить pipeline.
5. Проверить выполнение через Runner.

**Результат:** GitLab автоматически выполняет задания проекта.

**Проверка:** pipeline завершается успешно.

**Соответствие программе:** лекция 1.2 «Платформы непрерывной интеграции и доставки». 

---

## 5. 🟡 Настроить автоматический QA

**Дано:** CI/CD работает, но автоматическая проверка проекта отсутствует.

**Задача:** добавить QA в автоматизированный процесс.

**Решение:**

1. Подготовить проверку приложения.
2. Добавить QA в pipeline.
3. Запустить проверку через Runner.
4. Просмотреть результат.
5. Проверить реакцию pipeline на ошибку.

**Результат:** QA выполняется автоматически.

**Проверка:** результат проверки отображается в GitLab.

**Соответствие программе:** П.З.5 «Автоматический QA» и лекция 2.5 «Автоматизированный QA. SAST. DAST».  

---

## 6. 🟠 Выполнить SAST

**Дано:** автоматический QA настроен, но анализ безопасности кода отсутствует.

**Задача:** выполнить статический анализ безопасности.

**Решение:**

1. Подготовить SAST.
2. Настроить анализ проекта.
3. Запустить проверку.
4. Получить результаты.
5. Изучить обнаруженные замечания.

**Результат:** выполнен SAST приложения.

**Проверка:** результаты анализа доступны студенту.

**Соответствие программе:** лекция 2.5 «Автоматизированный QA. SAST. DAST» и Л.Р.2 «SAST».  

---

## 7. 🟡 Контейнеризировать приложение

**Дано:** FastAPI-приложение прошло предусмотренные проверки.

**Задача:** подготовить контейнер приложения.

**Решение:**

1. Создать Dockerfile.
2. Собрать Docker-образ.
3. Запустить контейнер.
4. Проверить приложение внутри контейнера.

**Результат:** FastAPI работает в Docker-контейнере.

**Проверка:** приложение отвечает после запуска контейнера.

**Соответствие программе:** лекция 3.1 «Технологии виртуализации и контейнеризации» и П.З.6 «VM, Docker, LXC-контейнеры».  

---

## 8. 🟠 Развернуть приложение в Kubernetes

**Дано:** приложение контейнеризировано.

**Задача:** выполнить его развёртывание средствами Kubernetes.

**Решение:**

1. Подготовить Kubernetes.
2. Создать конфигурацию приложения.
3. Развернуть контейнер.
4. Проверить состояние приложения.
5. Проверить его доступность.

**Результат:** приложение работает в Kubernetes.

**Проверка:** Kubernetes показывает работающее приложение.

**Соответствие программе:** лекция 3.2 «Оркестрация контейнеров Kubernetes» и П.З.7 «Kubernetes».  

---

## 9. 🟠 Настроить Prometheus

**Дано:** приложение работает в Kubernetes, но мониторинг отсутствует.

**Задача:** организовать мониторинг метрик.

**Решение:**

1. Подготовить Prometheus.
2. Настроить получение метрик.
3. Запустить приложение.
4. Проверить сбор метрик.
5. Просмотреть полученные показатели.

**Результат:** Prometheus получает метрики.

**Проверка:** необходимые метрики доступны в Prometheus.

**Соответствие программе:** лекция 5.1 «Мониторинг метрик и алертинг с использованием Prometheus» и П.З.12 «Prometheus в Minikube».  

---

## 10. 🟠 Настроить Grafana

**Дано:** Prometheus получает метрики, но удобная визуализация отсутствует.

**Задача:** визуализировать состояние FastAPI-приложения.

**Решение:**

1. Подготовить Grafana.
2. Подключить источник метрик.
3. Создать простой dashboard.
4. Добавить показатели приложения.
5. Проверить изменение показателей при обращениях к приложению.

**Результат:** состояние приложения визуализируется в Grafana.

**Проверка:** dashboard отображает полученные показатели.

**Соответствие программе:** лекция 5.2 «Визуализация в Grafana» и П.З.13 «Grafana (мониторинг FastAPI в Minikube)».  

---

## 11. 🔴 Проверить полный процесс

**Дано:** все предусмотренные проектом компоненты настроены.

**Задача:** проверить их совместную работу.

**Решение:**

1. Изменить FastAPI-приложение.
2. Зафиксировать изменение в Git.
3. Передать изменение в GitLab.
4. Запустить CI/CD.
5. Выполнить автоматический QA.
6. Выполнить SAST.
7. Собрать Docker-контейнер.
8. Развернуть приложение в Kubernetes.
9. Проверить приложение.
10. Проверить метрики в Prometheus.
11. Проверить визуализацию в Grafana.

Полная цепочка:

**Git → GitLab → GitLab Runner → CI/CD → QA → SAST → Docker → Kubernetes → Prometheus → Grafana.**

**Результат:** создан единый учебный процесс автоматизированной проверки, развёртывания и мониторинга приложения.

**Проверка:** все предусмотренные рабочей программой компоненты работают совместно.
